# 1.2.3 Bug 修复记录

## 用户反馈

- 当前歌词自动回正后仍位于屏幕底部，要求当前歌词严格位于屏幕中央。
- 音量偏大、调节有阶跃感，并担心界面音量与实际媒体音量不一致。
- 修复新问题时不得破坏已经完成的封面、进度、音质、音量、菜单和系统集成。
- 每个版本必须保留独立日志和安装包。

## 根因

歌词 TextView 通过 `paddingTop/paddingBottom` 预留半屏空间。旧居中公式只使用 `Layout.getLineTop()`，没有加 `TextView.getCompoundPaddingTop()`。因此计算出的 `scrollY` 少了顶部留白高度，当前歌词视觉位置向屏幕底部偏移。

## 修复设计

- 居中目标使用：`compoundPaddingTop + (firstVisualLineTop + lastVisualLineBottom)/2 - viewportHeight/2`。同一句歌词自动换成多行时，按整个高亮块居中，而不是只居中第一视觉行。
- 初次播放、每秒歌词切换和手动滚动停止三秒后的回正统一使用同一公式。
- 自动回正后记录当前行中心、视口中心和误差，真机要求误差不超过一行高度。
- MediaSession 显式声明本地 `USAGE_MEDIA` 播放；系统 `STREAM_MUSIC` 是唯一音量真值。
- 真机确认 OWW221 的音乐音量范围为 `0-16`，界面与按键均回读这个实际档位，不再维护固定 65% 或另一套应用音量。
- 播放状态更新时记录当前/最大系统音量，便于定位设备输出过响和状态不同步；网络播放器保持 unity gain，不做额外数字放大。
