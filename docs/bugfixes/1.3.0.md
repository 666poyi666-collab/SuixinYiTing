# 1.3.0 - 播放页与歌词页性能优化

## 需求

- NFR-007：播放页切换到歌词页时保持流畅，不因歌词初始化或背景更新掉帧。
- NFR-008：歌词页触摸/表冠上下浏览时不被每秒状态更新打断。
- NFR-009：降低歌词与封面渲染的内存、CPU 和 GPU 开销，暂停时停止无效轮询。

## 问题与根因

- BUG-026：服务每秒广播完整 `lyricAll` 和新建歌词窗口数组，产生 Binder/GC 压力。
- `NetworkPlaybackBridge` 每秒重建整首歌词 Spannable、重新 `setText`、重新布局并触发平滑滚动。
- 用户手动滚动期间仍会因当前歌词变化重建 TextView，导致触摸滚动卡顿。
- 2048x2048 封面原尺寸解码并重复绑定背景 View，增加内存和纹理上传成本。
- 暂停状态仍保持每秒 ticker，持续做无变化的广播和 UI 工作。

## 基线

- 设备：OPPO OWW221 / API 30，版本 1.2.9。
- `gfxinfo`：178 frames，102 janky（57.30%），P90/P95 150 ms，43 missed vsync。
- 初次 `meminfo` 峰值：TOTAL PSS 233,769 KB，Graphics 129,720 KB；后续稳定采样 Graphics 20,280 KB，说明封面/页面纹理生命周期存在明显波动。

## 实现记录

- 状态广播区分轻量 ticker 与完整歌词状态；完整歌词只在换歌、歌词解析完成和页面主动请求时发送。
- Activity 合并增量 Bundle，歌词按 revision 缓存。
- 歌词文本只在歌词 revision 或当前行变化时渲染；手动滚动期间延迟高亮更新到三秒回中。
- 将非当前歌词样式下沉到 TextView，全曲只为当前行创建三个 Span。
- 页面不可见或切换中时使用即时预定位，完全可见后才执行平滑回中。
- 封面按手表实际像素降采样，且相同 Bitmap/Activity 只绑定一次。
- 暂停后停止 ticker；恢复播放时再启动。歌词索引改为二分查找。
- 播放页生命周期驱动 ticker：退到后台或熄屏时停止 UI 进度广播，音频和 MediaSession 继续工作；回到前台主动回填完整状态。
- 固定的歌词字号、行距、颜色和音质行样式只在 View 首次绑定或音质变化时设置，不再随每秒进度重复触发布局。
- 音质和完整歌词解析结果切回主线程发布，避免后台线程读取 `MediaPlayer` 状态。

## 测试计划

- [x] PERF-01：最终 APK 包含六次歌词滑动和播放页往返的采样为 576 帧、220 janky（38.19%），P90 26 ms、P95 32 ms、missed vsync 1。ADB 注入带来 449 次 high input latency，因此该值用于版本相对比较，不作为纯手势延迟上限；前一轮热态采样为 26.86%。
- [x] PERF-02：歌词页连续触摸上下滑动不再被 ticker 拉回；停止三秒后日志确认当前逻辑歌词第 23-24 行按 496 px 视口居中，`animate=true`。
- [x] PERF-03：播放页/歌词页往返后标题、封面、完整歌词和当前行保持一致。
- [x] PERF-04：暂停 10 秒后 CPU 0%、新增渲染帧 0、missed vsync 0；恢复后 MediaSession 回到 PLAYING。
- [x] PERF-05：2048x2048 封面按 sample 4 解码为 512x512；最终采样 TOTAL PSS 41,487 KB、Graphics 6,100 KB。后台播放 8 秒记录 `UI active=false`、CPU 0%，回到前台后状态立即恢复。
- [x] AUD-01：seek 到 181,306 / 227,161 ms，MediaSession position 同步且保持播放。
- [x] UI-02/UI-09：378x496 真机封面、完整歌词和两行音质信息存在，无崩溃。
- [ ] SMK-01 至 SMK-07：本轮已验证登录保留、1242/1242 资料库、1230 随机池、网络播放和 MediaSession；其余扩展设置留到发布前完整回归。
